# Exact task39/task40 activation: static evidence

Source: canonical 06-libipas_sysc.so and prior canonical HMI registry probe. All addresses below are ELF st_value addresses. The fresh Ghidra project adds 0x10000 to these addresses; sysc.txt and detail.txt use that added base. No vendor execution performed.

1. Task1 tsk_sys_System calls SysPreInit -> SysSynInit -> SysInit. SysPreInit (0xbc78) zeros bf_sys_SysMng, sets field+4=0xff, initializes services, calls SysResInit, assigns runtime task-state byte0=1 to enabled tasks2 onward.
2. SysResInit (0x24020; sysc.txt:3124+) creates enabled tasks2 onward using rq_tsk_Create(config+.1c, config). It ORs runtime+.30 with1; additional config+.24 bits require types4..7. Task39 type3 and task40 type5 both have additional bits0, so both masks=1. Creation does not start pthreads.
3. SysInit (0xb994; sysc.txt:362+) starts enabled types4/7/8 and marks state2. Tasks39/40 remain state1.
4. Initial control: AccStart (0xad50; sysc.txt:1+) reads 8-byte synchronization value. If equal to sign-extended int32 at *tb_sys_PrcInf+.44 (PRC record1 offset4; GOT ELF0x318bc resolves tb_sys_PrcInf) it writes SysMng+.24=2, else1. SysSynInit (0xbbdc; sysc.txt:466+) optionally waits for process synchronization when process profile+.8==1; mode2 sets rq_sys_SetAcc(1). Separately queue1 message words [*,10,payload,*] reach RcvPrcCtl(0xb960; sysc.txt:344+): payload0 setsAcc1, nonzero setsAcc0. Do not infer a physical ACC state or fabricate an upstream producer from this.
5. SysCyclic (0xb8fc; sysc.txt:311+) invokes SysChk. SysChk (0xb7b4; sysc.txt:250+) sets effective mask bit1 according to GetAcc()==1. If effective-mask value differs from SysMng cached mask at+0, it computes changed_bits=old XOR new, updates cache, calls SysOnCtl(changed_bits), then SysOffCtl.
6. SysOnCtl (0x23bcc; sysc.txt:2923+, detail.txt:3731+) scans enabled tasks2 onward. Exact gate: (changed_bits & runtime+.30)!=0 && rq_sys_GetAcf(runtime+.30)!=0. State1 calls AccOnStop; states2/3 call AccOnInitAct; state7 calls AccOnShutPrc. GetAcf(mask) returns bool(mask & effective_mask) (detail.txt:1453+).
7. AccOnStop (0x22bdc; sysc.txt:2198+) starts config+.1c for types1..6 and8, then writes runtime state2. Type7 instead sends a configured status notification or callback. Thus task39/type3 and task40/type5 start through the SAME verified state1/effective-mask edge. AccOnInitAct (0x22a48) does nothing for either type; it acts only on type7. No arbitrary task starts are warranted.
8. rq_sys_NtyTskSts(0) (0x1e02c; detail.txt:1655+) sends queue1 [0,3,self,0]. When startup mode is1/2 and self!=3, it then waits on flag1/value1. Task1 dispatches message type3 into RcvTskCond(self,0); state2 calls TskCondActInit (0x22e44; sysc.txt:2308+), marks state3, and releases registered WaitInit waiters targeting this task.
9. With startupmode1/2, TskCondActInit requires all enabled task records2..count-1 runtime state3 before Delay(1000) -> SycSynInit (0x2174c; sysc.txt:1249+). SycSynInit optionally performs another configured parent synchronization, sets mode0, runs configured CnfSetup+.14 callback list, then sets flag1/value1. This global startup barrier is distinct from display-ready flag2/value1.
10. rq_tsk_WaitInit(target) (0x20f04; detail.txt:2973+) increments waiter count, sends [0,5,self,target] through BlockBegin(queue1). RcvInitWait checks TARGET state: state3 -> InitWaitAct(self), decrement count and BlockEnd(self object); other valid states -> InitWaitNotAct(self,target), record self's wait target and clear timeout counter. This is readiness waiting, not task activation.

Prior root evidence separately proves task39 later sets flag2/value1 and task40 waits on it. The first basic-block/callback behavior and flags must remain separate from evidence of reaching the GUI or rendering.

Unknowns: the current physical/power condition, exact external producer/order of queue1 type10 control messages, success of parent synchronization endpoints, callback side effects, actual completion of every enabled task's readiness and global flag1 barrier, runtime outcome after starting tasks39/40. Static control flow does not prove these events occurred.
